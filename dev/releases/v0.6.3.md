# Airclone v0.6.3 — video thumbnails on Android, repeat playback, a resizable transfers panel

Video files finally get real thumbnails on Android instead of a blank tile, the
player can put a file on a loop, and the Transfers / Recent activity panel on
desktop can be dragged to whatever height you need.

## Android — video files get thumbnails

Browsing a folder of videos on Android showed a plain dark tile for every one of
them, whatever the file. Now each tile shows a frame from the video, the way it
always has on desktop.

Airclone captures video keyframes with libmpv, its video engine. On Android
libmpv decodes into a display surface, so there is no frame it can hand back to
be saved as a picture — every capture came back empty. Android also refuses to
let its media stack read from the local rclone engine over an unencrypted
connection, even though that connection never leaves your phone.

Both are fixed: Android now grabs the frame with the platform's own decoder, and
the loopback exemption is scoped to `127.0.0.1` and `localhost` only — nothing
else in Airclone may talk unencrypted to anything. Because this no longer starts
a whole media player per tile, thumbnails also fill in two at a time instead of
one, and take roughly a second each.

Two smaller improvements come with it:

- Videos that **open on black** — a fade-in, a slate, a camera warming up — no
  longer produce a black thumbnail. Airclone looks a little further into the
  file for a frame with a picture in it. This applies on every platform.
- A capture with nothing in it is **never cached**. Before, a blank frame could
  be written to the thumbnail cache and stay blank until you rebuilt it by hand;
  now the file simply keeps its kind icon.

## Repeat: play a file on a loop

The preview player has a **repeat** button, on every platform. Turn it on and
the video (or audio file) restarts the moment it ends, instead of stopping on
its last frame — useful for a short clip you want to watch a few times, or a
loop you are checking frame by frame.

The setting is remembered, so the next file you preview keeps looping until you
turn it off, and switching it mid-playback affects the file you are watching
right now, not just the next one. It sits in the player's own control bar —
next to fullscreen on desktop, at the end of the bar on a phone — and beside
play/pause on the audio card.

## Desktop — the transfers panel resizes

The **Transfers** / **Recent activity** panel at the bottom of the desktop
window was a fixed 240 pixels tall, which is not enough to see which transfers
finished when more than a few have run.

Drag its top edge to resize it — the same handle the split panes use. The height
is remembered between launches, and is re-checked against the window: a panel
sized on a large monitor shrinks to fit when the window is small, and it can
never grow so tall that the file panes disappear.

## Notes

- The Android fix is verified end-to-end on the emulator, against a real remote
  through the real engine. Video *playback* on the emulator is still black — the
  emulator cannot create a GL context for libmpv — but thumbnails no longer
  depend on that path.
- The desktop and iOS thumbnail path still uses libmpv and is unchanged, apart
  from the new blank-frame handling.
- Repeat is verified on Windows (a clip loops instead of freezing on its last
  frame) and on Android, where playback itself is confirmed by position rather
  than by picture, for the emulator reason above.
- Turning repeat on *after* a file has already finished does not rewind it —
  press play. It applies from the next time the file reaches the end.
