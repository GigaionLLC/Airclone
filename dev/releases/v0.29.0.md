# Airclone v0.29.0 — scheduled tasks never run twice at once; long uploads aren't cut off

## A task never runs on top of itself (#55)

A scheduled task whose run took longer than its interval used to start again
while the first run was still going, so one big upload could end up running
two or three times in parallel. Now a task only ever has one run at a time:

- **While it's still running**, the next scheduled slot is skipped. It isn't
  lost: the task starts once more as soon as the current run ends. Saved tasks
  shows a line when this happens.
- **Run** on a task that's already running tells you so instead of starting a
  second copy.
- **This holds across Airclone's background runs too** ("run while Airclone is
  closed"): the open app and a background run can no longer run the same task
  together.

## Long uploads are no longer stopped after 6 hours (#54)

Scheduled and background runs were stopped after 6 hours, even when they were
making steady progress. On a slow connection a big file could never finish,
and providers like Google Drive start a stopped file again from zero. Now:

- A run is stopped only if it makes **no progress for 60 minutes**, and it's
  recorded as failed with that reason.
- A run that keeps moving can go on for up to **72 hours**.
- On Windows, scheduled tasks you already set up are updated to the new limits
  the next time Airclone opens. Each one may run once straight after the
  update.

## Notes

- iPhone, iPad and Android background runs still follow the time limits the
  operating system sets.
