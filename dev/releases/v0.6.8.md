# Airclone v0.6.8 — no app changes; Microsoft Store publishing, and a pipeline check

**If you are already on v0.6.7, this update changes nothing you can see.** The
app is the same feature set; only the machinery that builds, submits and
publishes it changed.

Microsoft Store submission is now a workflow rather than an evening of clicking:

- Submission runs from the Actions tab against an already-built release, so what
  gets certified is the exact signed package that was tested — never a rebuild.
- **Package identity is checked before Partner Center sees it.** Identity
  mismatches cost this app four review cycles once, and Partner Center validates
  those fields in a fixed order so the first failure hides the rest. Catching it
  in CI turns days into seconds.
- A newer build can now **supersede one still in certification**, so a release
  never has to wait behind an older one under review.

It is also a deliberate end-to-end test of the release pipeline. An unproven
publishing path is how a project discovers, weeks later, that it silently
stopped shipping — so the tag itself is part of the point.

## Notes

- Windows binaries are code-signed (Gigaion, LLC) and bundle a verified rclone
  v1.75.0 engine; macOS is Developer ID signed + notarized; Android APKs are
  release-signed.
- Android continues to publish automatically to open testing on a tag, with
  promotion to production a separate, deliberate button.
