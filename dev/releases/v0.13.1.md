# Airclone v0.13.1 — the preview menu, on every platform

v0.13.0 put delete in the preview window, and the two commits after it added rename, copy path,
public link and checksums. This release is about where those actually appeared, which turned out to
be less than "in the preview".

## They were phone-only. Now they are not.

Public link, checksums and copy path lived in the `⋯` sheet, and that sheet only exists in the phone
shape of Quick Look. On a desktop there was no way to reach them from the preview at all, even though
nothing about them is phone-specific.

The preview toolbar now has a `⋯` of its own, with the same menu.

## They vanished entirely on iPhone and iPad

The `⋯` button was shown only when the system can hand a file to another app. iOS cannot, so the
button was never drawn there — and it was carrying delete, rename, public link, checksums and copy
path with it. Five operations, absent on a platform, because of a sixth that has nothing to do with
them.

The two entries that genuinely depend on the platform are now gated on their own: **Open in another
app** is hidden where there is no route for it, and **Share…** appears only on phones, where the
system has a share sheet. Everything else is always there.

## One list

Both shapes now render one ordered list of actions, so an operation added later shows up on every
platform without anybody remembering to add it twice. Which entries are offered is a plain function
of what the platform can do, and it has tests: the menu is never empty, the file operations are
present on every shape, and delete is always last and set apart from the rest.

## Notes

- No change to what any of the operations do. Only where you can reach them.
- The smaller Preview dialog still has delete and nothing else, on purpose: it opens from the details
  panel, where `Copy path` and `Copy link` sit a row away from the button that opened it.
- Copy to and move to another folder are still absent from the preview. They need a destination, and
  choosing one from inside a fullscreen overlay is a design problem rather than another menu entry.
- Windows builds are signed; macOS builds are Developer ID signed and notarized.
