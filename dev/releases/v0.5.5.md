# Airclone v0.5.5 — self-contained install, clean uninstall

Fixes the three findings from the Microsoft Store certification report of
2026-07-29. Two of them are real defects that affected **every** Windows user, not
just Store installs.

- **The install is now genuinely self-contained.** The Microsoft Visual C++ runtime
  (`msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll`) now ships next to
  `airclone.exe`. Before this, Airclone silently depended on the *Visual C++
  Redistributable* being installed already — on a clean Windows machine that had
  never seen a C++ app, it would refuse to start. Nothing to install, nothing to
  download.
- **Closing the window now stops the rclone engine.** It never did: Windows does not
  end a child process with its parent, so every session left an `rclone.exe`
  daemon running in the background until the next launch reaped it.
- **Uninstalling is clean.** Because of the leak above, the stray daemon held the
  engine binary open inside the install folder and the uninstaller could not remove
  it, leaving files behind in `C:\Program Files\Airclone`. Airclone now also puts
  every rclone process it starts into a Windows job object, so even a crash cannot
  orphan one, and the uninstaller sweeps the install directory regardless.
- **The uninstaller offers to remove Airclone's own data** — its settings and cached
  thumbnails — so removal can be complete. Decline and they are kept for a
  reinstall. Your `rclone.conf` is never touched: it belongs to rclone and is shared
  with the rclone command line.

## Notes
- Still **pre-1.0**. Windows `airclone.exe` + installer are code-signed (Gigaion,
  LLC) and bundle a verified rclone engine; macOS is Developer ID signed + notarized;
  Android APKs are release-signed.
- The Windows build now hard-fails in CI if the Visual C++ runtime is not bundled,
  so this cannot regress silently.
