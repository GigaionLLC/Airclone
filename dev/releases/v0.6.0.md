# Airclone v0.6.0 — previews that work, and files that open anywhere

Mostly a response to one Play review: *"the preview function for video files
stored in the cloud often doesn't work."* It turned out not to be one bug but a
whole class of them — failures that were completely invisible.

## Video and photo previews

- **A video that can't play now says so.** Previously any failure — an
  unsupported format, a dropped connection, a file that isn't really a video —
  showed a black rectangle that never played, indistinguishable from a slow
  load. Preview now tells you what went wrong and offers **Try again** and
  **Open in another app**, so a video Airclone can't decode is one tap from a
  player that can.
- **You can see it loading.** A slow cloud read shows a spinner until the first
  frame actually appears, instead of looking broken.
- **Video thumbnails no longer fight the video you're watching.** Building
  thumbnails is heavy work, and on a phone several at once starved playback.
  Phones now build them one at a time, with a longer budget for slow
  connections.

## Open anything in another app

- **New on Android, Windows, macOS and Linux.** Hand any file straight to the
  app you'd rather use — a video player, a photo viewer, an editor — or send it
  on with the share sheet. Cloud files are fetched first, with a progress
  dialog you can cancel; local files open immediately.

## A viewer that uses your whole screen

- **On phones and tablets**, tapping a photo or video now opens it edge to edge
  with the system bars hidden, the way a phone gallery does. Swipe between
  items, tap to hide the controls.
- **On desktop**, the preview fills the window instead of sitting in a fixed
  1100-pixel box — so a bigger window or a bigger monitor now actually gets you
  a bigger picture.

## Phones catch up with the desktop

- **Every desktop tool is now reachable on a phone.** The `⋯` menu gains an
  **Advanced** section — reload thumbnails, load a whole folder, rebuild the
  cache, Copy/Move/Sync this folder, compare with the other pane. It starts
  collapsed so the everyday actions stay one tap away.

## Desktop

- **Closing Airclone with drives mounted now asks first.** Mounted drives are
  the one thing closing Airclone takes away from other apps, so it warns before
  disconnecting them rather than pulling them out from under an editor with
  unsaved work.
- **Fixed the layout on Android tablets**, where the system clock and battery
  icons overlapped Airclone's own toolbar.

## Engine

- **Updated the bundled rclone to v1.75.0** (from v1.74.4).
- **"Update engine" actually works now.** If Airclone had ever downloaded an
  rclone engine for you, every later attempt to update it failed with "Update
  failed. Please try again." — it tried to overwrite the engine while that exact
  file was still running, which Windows does not allow. The new engine is now
  downloaded and verified first, the running one is stopped, and only then are
  they swapped. The previous engine is kept until the new one has started, so a
  broken release can't leave you without a working engine.
- **If you updated from an older Airclone and still see an old rclone version**,
  that is why: a previously downloaded engine takes precedence over the one
  bundled with the app. Settings → Engine → Check for updates now brings it
  current.

## Notes

- Still **pre-1.0**. Windows `airclone.exe` + installer are code-signed
  (Gigaion, LLC) and bundle a verified rclone engine; macOS is Developer ID
  signed + notarized; Android APKs are release-signed.
- The rclone update was checked against a real v1.75.0 build before shipping:
  ranged reads (which previews depend on) and remote setup both behave exactly
  as before, and the in-process engine builds and passes its round-trip tests on
  Windows, macOS and Linux.
- **Known limitation:** video *playback* is verified on desktop, where a clip
  plays start to finish. It could not be verified on Android hardware — the
  Android emulator cannot render video at all, and no physical device was
  available. The failure paths above are verified on Android; the success path
  is not.
