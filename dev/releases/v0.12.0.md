# Airclone v0.12.0 — you can see what is not on your disk

If you sync a cloud folder to your computer — OneDrive, iCloud, Proton Drive, Dropbox — some of
those files are not really there. Only a placeholder is. Airclone now shows you which.

## Files stored online only

**They are marked.** A file or folder whose contents are not on this device shows a **cloud outline**
instead of its usual icon. Previously it looked identical to any other file, and the only way to find
out was to open it and start an unexpected download.

**Opening one asks first.** Preview now shows the size and a button naming what it is about to fetch.
This was the real bug: one click on an online-only 4 GB video used to begin downloading 4 GB, on
whatever connection you happened to be on, with nothing saying so.

**Thumbnails stay off, unless you ask.** Right-click a marked file and choose `Show thumbnail
(downloads it)`. That choice lasts for the session only — a decision made on home wifi should not
still apply on a hotel connection next week.

**Transfers are unchanged.** Download, Copy, Sync and Backup proceed without asking, because there
the download is the thing you asked for. A prompt is for a download that would be a *side effect* of
looking at something.

**macOS is covered now.** This protection was Windows-only. A Mac browsing iCloud Drive or Dropbox
got exactly the silent download it exists to prevent.

## The Web UI

**It tells you what your browser cannot play.** A browser brings its own video decoder and it is a
narrow one: MP4, WebM and Ogg play; AVI, MKV, WMV and FLV do not, in any web page. Airclone used to
show the browser's raw error next to a `Try again` button that could never work. It now names the
format and points at Download, or at the desktop app, which plays all of them.

**It has Airclone's icon.** The favicon, the install icons and the page title were still Flutter's
defaults — the description even read "A new Flutter project."

## Security

A full audit, self-review then adversarial review. The findings worth naming:

- **The engine password is no longer visible to other users on the machine.** It was passed on
  rclone's command line, where any other account could read it.
- **A crafted video playlist could open a local file.** The media player ran with a default
  configuration that permitted `file://` sub-resources; a `.m3u8` naming one would have opened it.
- **The engine's credentials no longer travel past the machine.** They were attached to every request
  the player made for a stream, so a playlist could have named a segment on someone else's server and
  been handed them.
- Private keys and the Web UI password are now written to disk already locked down rather than
  locked down a moment later.

None of these are known to have been exploited; they are what an audit is for.

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- The online-only detection covers Windows and macOS. Linux sync clients do not expose the same
  information, so files there are treated as local.
