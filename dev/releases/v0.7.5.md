# Airclone v0.7.5 — "Copy to" can reach your own drives

## What is fixed

- **"Copy to…" and "Move to…" now offer your local disks and saved folders**, not
  only your cloud remotes. Choosing a drive from that dialog was simply not
  possible before: the list held cloud remotes and your home folder, so copying
  onto a disk meant opening it in a pane by hand and pasting — a workaround
  nobody picked on purpose, because it was the only route.

  The dialog now shows the same three groups as the sidebar, with the same names
  and icons: **Locations**, **Disks**, **Cloud**.

- **Local disks stay available when the engine is not.** The cloud list needs the
  rclone engine, and while it was loading or failing it used to replace the whole
  dialog. Local disks need no engine, so they now stay usable and only the cloud
  section shows the spinner or the error.

## Notes for the curious

Nothing was broken in the copy itself — the dialog simply had never been told
that local drives exist. Airclone keeps them in a different place internally from
cloud remotes, and the picker only ever read the cloud one. Everything it needed
was already in the right shape; it just had to ask.

The same dialog is behind **Copy to**, **Move to** and **Transfer to**, so all
three gained this at once.

## Also in this release

- The bundled rclone engine remains **1.75.1**, the security release from 0.7.3.

## Verified

- Full test suite green (740 tests), including coverage for the case that would
  otherwise slip back unnoticed: with the engine unavailable, the local disks
  must still be offered.
