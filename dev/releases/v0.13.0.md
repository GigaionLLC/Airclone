# Airclone v0.13.0 — delete from the preview

Asked for in [issue #4](https://github.com/GigaionLLC/Airclone/issues/4): *"The preview window should
allow delete and operations. Please prioritize delete."*

## Delete without leaving the preview

Both preview surfaces now have a **delete** button — Quick Look's toolbar, the preview dialog's
header, and the `⋯` sheet on a phone. It asks first, with the same confirmation the file list uses.

The part that makes it worth having is what happens next: **Quick Look stays open and moves to the
next file.** Going through a folder of photos and removing the bad ones is now one confirmation per
file, rather than preview → close → find the file → delete → reopen → find your place. It closes when
the last file is gone.

The folder behind the preview re-lists immediately, so what you see is what is actually there. A
delete that appeared to do nothing until you navigated away would be worse than no button at all.

## A note on where the button sits

Delete is placed *before* Close and spaced away from it, in both surfaces. They sit next to each
other and only one of them is undoable. In the phone sheet it is last, behind a divider, for the same
reason.

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- Other file operations from the preview — rename, copy, move — are not here yet. Delete was asked
  to come first, and it has.
