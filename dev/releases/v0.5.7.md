# Airclone v0.5.7 — uninstall works even with Airclone open

One fix, found by running a real per-machine install → uninstall cycle rather
than trusting the installer script to behave.

- **Uninstalling while Airclone is still open now removes everything.** Windows
  would not let the uninstaller delete files that a running Airclone had open, so
  a folder was left behind in `C:\Program Files\Airclone` unless you quit the app
  first. The uninstaller now closes anything still running from its own install
  folder before it starts. Nothing you run from anywhere else is touched — not
  your own copy of rclone, and not a second Airclone installed just for your user
  account.

## Notes
- Still **pre-1.0**. Windows `airclone.exe` + installer are code-signed (Gigaion,
  LLC) and bundle a verified rclone engine; macOS is Developer ID signed + notarized;
  Android APKs are release-signed.
- Everything from v0.5.5 and v0.5.6 is included: the app-local Visual C++ runtime,
  engine shutdown on window close, the fix for setting up a remote when the
  provider asks a follow-up question, and actionable command-console messages.
- Verified end to end on Windows 11: silent per-machine install (exit 0), launch,
  then a silent uninstall **with the app running** → install directory gone,
  no leftover processes, Add/Remove Programs entry gone, uninstaller exit code 0,
  and settings + `rclone.conf` deliberately preserved.
