# Airclone v0.7.1 — three field reports

Three things people told us were wrong. Each one turned out to have its cause
somewhere other than where the symptom pointed.

## What is fixed

- **Windows: Explorer no longer freezes on a mounted drive.** After a burst of
  transfers, File Explorer could wedge on an rclone drive mounted from Airclone
  and only recover when Airclone itself was closed. That last detail was the
  clue: closing Airclone is what fixed it, so the cause was ours. Airclone was
  not reading the rclone engine's log output, and a pipe nobody reads blocks the
  program writing to it — which, for rclone, means every part of it that logs
  next, including the part serving your mounted drive. It is read now.
- **Android TV: the remote can reach the buttons.** A Google TV user could open
  "Import File Config", choose a file and type the passphrase, but could not
  move the focus onto **Unlock** — and hit the same wall trying to pick a
  storage type when adding a remote. Two separate causes, both fixed: dialogs
  now get a focus ring and a starting focus (they had neither), and the D-pad's
  up/down can now leave a text field instead of being swallowed to move the
  cursor inside it.
- **The transfers list uses the space you give it.** The bottom Transfers dock
  has been resizable since v0.6, but the live list of files actually moving sat
  in a fixed box inside it — so dragging the dock taller grew everything except
  the part you were trying to read. It now takes half the dock and scrolls, the
  divider is visible and can be double-clicked to expand, the dock's tab strip
  has an expand button, and a transfer moving more files than its row shows now
  has a "show all" you can click instead of a dead "+4 more". The same live list
  on phones and TV got the same fix.

## Notes for the curious

The mount freeze is the interesting one. Airclone runs rclone as a child
process, and a child's output goes into a pipe. Nobody had to read that pipe for
anything — the log was only printed in development builds — but an unread pipe
does not discard what is written to it, it *stops the writer*. On Windows that
pipe holds one kilobyte. rclone writes its log under a single lock, so once one
message was stuck, the next thing that tried to log waited behind it, and so did
everything after that, including the code answering Explorer's requests for your
mounted drive. Explorer waits on those requests, so Explorer froze. Closing
Airclone closed the pipe, which released the writer, which is why killing the
app fixed a problem the app appeared to have nothing to do with.

Release builds were the only ones affected, because they were the only ones not
reading the log.

## Also in this release

- The dock can no longer be dragged shorter than its own contents. Its minimum
  was smaller than the panel header it had to hold, so dragging it all the way
  down clipped it.
- If the engine ever stops answering, Airclone now records that in the local
  problem report (Settings → Diagnostics), so a freeze leaves evidence behind
  rather than just a spinner.

## Verified

- **Android TV emulator, API 36, 1080p, D-pad keys only.** Every step of the
  reported flow: an encrypted config's **Unlock** button reached by pressing
  down from the passphrase field and activated; "Add a remote" opened, its
  search field left with one press, a storage type selected, and the form's
  primary button reached the same way. Focus was visible in every frame.
- Windows: release build; full test suite green (708 tests), including new tests
  covering the dock at every height the shell can give it and the two TV focus
  traps.

## Known gap (not a regression)

Android TV has no system file picker — `ACTION_OPEN_DOCUMENT` resolves to a stub
on a stock TV image — so "Import File Config" cannot browse for a file on
devices that ship without one. Devices with a file manager installed are
unaffected. "Import QR Config" is the path that always works on a TV.
