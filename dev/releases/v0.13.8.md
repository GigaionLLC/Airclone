# Airclone v0.13.8 — updating from a terminal, and a crash on Linux

## Closing a popped-out image window no longer closes Airclone

On Linux, popping an image into its own window and then closing that window took
the whole app with it — including any transfer that was running.

It was not Airclone's bug. The plugin that makes extra windows gives each one its
own engine, and then removes something on close that the Flutter engine refuses
to remove; the process dies. A bare test app with that plugin as its only
ingredient fails exactly the same way, and the newest release of it does this.

**So Linux does not offer pop-out windows in this version.** Images open in the
in-app viewer instead — the same picture, the same next/previous, the same
controls. Windows and macOS are unaffected and keep pop-out windows.

We also tried a patched copy of the plugin: it stops crashing and freezes
instead, which is not better. Pop-out will come back to Linux when the plugin is
fixed upstream, and there is now a test that says when that has happened.

## `airclone --update`

Airclone can update itself from a terminal, the way `rclone selfupdate` does:

```
airclone --update                          # check, download, verify, install
airclone --update --check                  # say what would happen, change nothing
airclone --update --output ./new.AppImage  # save the verified file, install nothing
airclone --update --version-tag v0.13.7    # a specific release, including going back
```

Settings → Updates gains the same thing as a button.

**It will not install anything it cannot prove came from this project.** Before
installing, it checks a signature over the release's checksum list, then that
release's checksum for your exact download. If either is wrong it deletes what it
downloaded and leaves your version alone.

**Not switched on yet.** These builds carry no release key, so for now `--update`
and the button will say so and point you at the releases page. The next release
is expected to carry one, and nothing installs itself until then.

It refuses in two other cases, on purpose:

- **Installed from a store** (Microsoft Store, Google Play, the App Store, the
  Mac App Store, Flathub, Snap) — those deliver their own updates, and their
  rules say an app must not go around them. It names the store instead, and makes
  no request to GitHub at all.
- **A package that cannot replace itself** — the tar.gz, the Windows portable zip
  and the macOS app download and verify, then tell you where the file is. The
  AppImage and the Windows installer install themselves.

## Smaller things

- Every release from now on publishes a **`SHA256SUMS`** file, so a download can
  be checked by hand: `sha256sum -c SHA256SUMS --ignore-missing`.
- The update check on the Settings screen compares versions properly. It used to
  ask whether the newest tag *contained* your version, so anyone on 0.9.1 was
  told they were up to date for the whole life of 0.9.10.
- The README says plainly that Airclone is new and in beta, and asks for issues.

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- This release is on GitHub only and has not been sent to any app store.
