# Airclone v0.7.6 — three ways to lose data, closed

Every fix in this release is the same shape: an operation that destroyed
something and reported success.

## What is fixed

- **Downloading, dragging in, and sending to the other pane no longer overwrite
  silently.** Paste, "Copy to…" and "Move to…" have always asked before
  replacing a file. Five other paths did not: Download (from the toolbar, the
  inspector, and a selection), files dragged in from Explorer or Finder, and the
  ⇄ transfer-to-other-pane button. rclone replaces by default, so a same-named
  file at the destination was gone — no prompt, no warning, nothing to undo.

  All five now ask the same Skip / Replace / Keep both question as the rest, and
  refuse outright when the destination can't be read rather than assuming it is
  empty. The pane-to-pane transfer also stops clearing your selection when you
  cancel, which previously made a cancelled transfer look exactly like a
  completed one.

- **Creating a remote can no longer overwrite one that already exists.** Typing
  the name of an existing remote in either wizard replaced it — no warning, no
  confirmation, nothing in the result to say anything had been lost.

  On an encrypted remote this was silent data loss. The files stayed where they
  were, but a new password or salt cannot decrypt their names, so they were
  skipped and the folder appeared **empty**. Nothing anywhere reported an error,
  and the encryption wizard's own verification step still passed — it only ever
  proved the new key was consistent with itself, not that it could read what was
  already there.

  Both wizards now refuse a name that is taken, and refuse just as firmly when
  the existing remotes can't be listed at all. Editing a remote is unchanged; it
  was always a separate, deliberate action.

## Notes for the curious

If a remote of yours already shows as empty and you believe it is not, this
release does not repair it — the data is intact and the configuration is what is
wrong. The remote's password and salt no longer match what its contents were
encrypted with. Correcting that entry in your rclone configuration brings the
files back; nothing was deleted.

## Also in this release

- The iOS release lane no longer authorises Xcode to create signing certificates
  on its own during export. It only ever needed that for one deliberate
  experiment, and leaving it on the shipping path is how ten unused certificates
  accumulated against Apple's account limit.
- The bundled rclone engine remains **1.75.1**.

## Verified

- Full suite green: **744 tests**, plus `flutter analyze` and `dart format`.
- Both new guards were confirmed to **fail without the fix** before being kept —
  the download prompt genuinely absent, and `config/create` genuinely firing on a
  name that already existed. A regression test that has never failed proves
  nothing.
