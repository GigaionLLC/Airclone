# Airclone v0.20.0 — the engine layer is its own package now

**Almost nothing in the app looks different**, and that is the point: this release moves the
code that drives rclone out of Airclone and into a package, so other people can build on it
and so a bug in it gets fixed once, in one place. Everything you do with Airclone works as it
did in v0.13.9.

The exception is worth reading, because it is the kind of bug you would never see happen: a
file could be overwritten without Airclone asking first. Moving this code is what exposed it.

## What moved

The part of Airclone that starts rclone and talks to it — the interface, the spawned
`rclone rcd` engine, the in-process `librclone` engine, the byte bridge that serves previews
— is now a separate Dart package called **`airclone_rc`**, living in the same repository.
Airclone uses it like any other dependency.

It was prompted by [a request](https://github.com/GigaionLLC/Airclone/issues/6) from someone
building a different app on rclone, who asked whether they could reuse this piece rather than
write it again.

## Three real fixes came out of it

**A file could be overwritten without being asked about.** Copying or pasting into a folder
first reads what is already there, so Airclone can ask before replacing anything. If that
read *failed*, it refused to continue — correctly. But if the engine answered without a
listing in it, which is not the same as an empty folder, that answer was read as "there is
nothing here to overwrite" and the copy went ahead silently. An empty-looking listing is also
exactly what a crypt remote with the wrong second password returns. Both places that check
now treat "I could not read this" and "this is empty" as the different answers they are.

**Two programs could kill each other's engine.** Airclone cleans up `rclone rcd` processes
left behind by a crash or a force-quit. It found them by name in your system's temporary
folder, and those names were fixed. That was fine while Airclone was the only program that
behaved this way. As soon as a second app used this code, the two would have found each
other's leftovers and killed each other's running engine — the other app's window would
simply lose its connection mid-copy. Each program now names its own, and Airclone keeps the
names it always used, so an engine left behind by an older version is still cleaned up when
you upgrade.

**Engine logs are scrubbed twice now, not once.** Airclone already removed credentials from
diagnostic lines as they arrived. The engine layer now removes its own session's password
before handing a line over at all — which matters most for anyone *else* building on this
code, since at high verbosity rclone announces that password before it has served a single
request.

## For anyone building on it

`airclone_rc` is AGPLv3 like Airclone, ships no rclone binaries — you supply your own
`rclone` or `librclone` — and is not on pub.dev yet, though a git dependency on this
repository works today. It also has a typed API now: `rc.operations.list(...)` rather than
method strings, across `core`, `config`, `operations`, `job`, `sync`, `mount`, `serve` and
`vfs`. Airclone itself has moved onto it, which is how the first of the fixes above was
found. The plan and its current state are in `dev/plans/airclone-rc-package-plan.md`.

## Notes

- No settings, no remotes, no mounts and no scheduled tasks are affected by this release.
- Every platform is built and tested from the same package: Windows, macOS, the Mac App
  Store, Linux, Android and iOS.
- The version jumps from 0.13.9 to 0.20.0. Nothing is missing in between: the number marks
  the release where the engine layer became a package, and it was chosen when that work was
  planned.
