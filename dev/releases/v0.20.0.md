# Airclone v0.20.0 — the engine layer is its own package now

**There is nothing new to see in the app.** Everything works exactly as it did in v0.13.9.
This release moves the code that drives rclone out of Airclone and into a package, so other
people can build on it — and so a bug in it gets fixed once, in one place.

## What moved

The part of Airclone that starts rclone and talks to it — the interface, the spawned
`rclone rcd` engine, the in-process `librclone` engine, the byte bridge that serves previews
— is now a separate Dart package called **`airclone_rc`**, living in the same repository.
Airclone uses it like any other dependency.

It was prompted by [a request](https://github.com/GigaionLLC/Airclone/issues/6) from someone
building a different app on rclone, who asked whether they could reuse this piece rather than
write it again.

## One real fix came out of it

Airclone cleans up `rclone rcd` processes left behind by a crash or a force-quit. It found
them by name in your system's temporary folder, and those names were fixed. That was fine
while Airclone was the only program that behaved this way. As soon as a second app used this
code, the two would have found each other's leftovers and killed each other's running
engine — the other app's window would simply lose its connection mid-copy.

Each program now names its own. Airclone keeps the names it always used, so an engine left
behind by an older version is still cleaned up when you upgrade.

## For anyone building on it

`airclone_rc` is AGPLv3 like Airclone, ships no rclone binaries — you supply your own
`rclone` or `librclone` — and is not published to pub.dev yet. The plan and its current state
are in `dev/plans/airclone-rc-package-plan.md`.

## Notes

- No settings, no remotes, no mounts and no scheduled tasks are affected by this release.
- Every platform is built and tested from the same package: Windows, macOS, the Mac App
  Store, Linux, Android and iOS.
