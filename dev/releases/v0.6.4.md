# Airclone v0.6.4 — a maintenance release

Nothing in Airclone works differently in this release. What changed is the
toolchain it is built with, and the PDF engine underneath the document preview.

If v0.6.3 is working for you, there is no reason to hurry — but these are the
builds every later release will be based on, so it is worth taking when
convenient.

## Built on a newer Flutter

Airclone is now built with Flutter 3.47. The version used to build a release is
pinned deliberately: the previous one moved on its own mid-release and broke
every platform build at once, which is a thing that should never be discovered
by a release.

Moving up required newer versions of the Android build tools (Gradle, the
Android Gradle Plugin, Kotlin) and — the one piece you might actually notice —
a new major version of the PDF engine.

## The PDF viewer sits on a new engine

Document previews use PDFium through the `pdfrx` package, and this release moves
from its 1.x line to 2.x. Opening, rendering, scrolling and zooming a PDF are
verified working on both desktop and Android.

The internals of text selection and of scroll/zoom handling were rewritten
upstream between those versions, so if a PDF behaves oddly for you — selection,
zoom limits, gestures — that is worth reporting: **Settings → Diagnostics →
Problem report** captures it, with your paths and credentials stripped before
anything is recorded.

## Notes

- No app code changed in this release beyond one small fix the newer analyzer
  found: a failure inside the Android thumbnail path could slip past the error
  handling written to catch it. It would have shown up as a video tile that
  stayed empty instead of retrying.
- Every platform build (Windows, macOS, Linux, Android) was built and checked on
  the new toolchain before this release was tagged, and the Android and Windows
  builds were run to confirm video thumbnails and PDF preview still render.
- Windows binaries are code-signed (Gigaion, LLC) and bundle a verified rclone
  v1.75.0 engine; macOS is Developer ID signed + notarized; Android APKs are
  release-signed.
