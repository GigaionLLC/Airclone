# Airclone v0.6.6 — no app changes; a publishing-pipeline verification

**If you are already on v0.6.5, this update changes nothing you can see.** The
app is byte-for-byte the same feature set; only the machinery that builds and
publishes it changed.

It exists because three changes to the release pipeline had not yet been proven
on a real tag, and an unproven publishing path is how a project discovers, weeks
later, that it silently stopped shipping:

- The Play upload switched to the `tracks:` input after Google deprecated the
  singular `track:`. Deprecated inputs do not fail — they get ignored, which
  looks like success and publishes nothing.
- The release now **asks Google Play what it actually holds** and fails if the
  version code just built is not in open testing. A step reporting success is
  not evidence anything landed.
- Three GitHub Actions were bumped off the deprecated Node 20 runtime.

## Notes

- Windows binaries are code-signed (Gigaion, LLC) and bundle a verified rclone
  v1.75.0 engine; macOS is Developer ID signed + notarized; Android APKs are
  release-signed.
- The user-facing fix in the previous release — a paste into a folder Airclone
  cannot read no longer overwrites blind — is unchanged and still current.
