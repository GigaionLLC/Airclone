# Airclone v0.6.5 — a safety fix, and the first release published automatically

A small release with one real fix in it. It is also the first Airclone release
that reaches Android by itself: tagging it publishes to Google Play's open
testing track with no manual upload.

## Pasting into a folder Airclone cannot read

Copying or moving files into a destination it could not list — an offline
backend, an expired token, a folder without read permission — Airclone treated
"I cannot see what is in there" as "there is nothing in there", and copied
straight over whatever was actually present. No prompt, no warning.

It now stops and tells you, instead of writing over a file it could not see.
The collision prompt you already know (Skip / Replace / Keep both) is unchanged
for destinations it *can* read.

This is the sharpest edge of a wider piece of work: the collision check today
only guards paste and drag-drop, while "Copy to…", "Move to…", downloads and
uploads still write without asking. That is scoped and queued as its own change
rather than quietly half-done here.

## Notes

- Windows binaries are code-signed (Gigaion, LLC) and bundle a verified rclone
  v1.75.0 engine; macOS is Developer ID signed + notarized; Android APKs are
  release-signed.
- Nothing else in the app changed. The remaining commits in this release are
  documentation and release automation.
