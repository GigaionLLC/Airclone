# Airclone v0.6.9 — no app changes; carries a Microsoft Store price correction

> **Drafted, never shipped — kept for the record.** These notes were written during the 2026-08-16/17
> Microsoft Store pricing incident and then abandoned: v0.6.9 was never tagged and never built, and
> no build number was spent on it (v0.6.8 is `0.6.8+117`, v0.7.0 is `0.7.0+118`). The price
> correction it was meant to carry went out as a fresh Partner Center submission instead, needing no
> new app version, and everything below is superseded by v0.7.0. The file stays because
> [`v0.7.4.md`](v0.7.4.md) names 0.6.9 to App Store readers catching up from 0.6.8, and because it is
> the clearest account of why the publishing tool now refuses `--commit`. The durable form of that
> lesson lives in `AGENT.md` (store rules 10-13), the advanced-pricing guard in `tool/store_submit.py`,
> and the 2026-08-17 entry in [`../logs/agent-changelog.md`](../logs/agent-changelog.md).

**If you are already on v0.6.8, this update changes nothing you can see.** The
app is the same feature set.

It exists to carry a Store submission that restores the correct listing price.
The v0.6.8 Store submission was committed through the Store's REST API, and for
a product using Microsoft's *advanced pricing model* that API cannot express the
real price — it publishes the listing at zero. The submission had already passed
certification and entered publishing before that was caught.

The publishing tool now refuses to commit through the API for such a product at
all. Store submissions are staged by machine and submitted by a human from
Partner Center, which is the path that preserves pricing correctly — the same
path that published v0.6.7 at its proper price.

## Notes

- Windows binaries are code-signed (Gigaion, LLC) and bundle a verified rclone
  v1.75.0 engine; macOS is Developer ID signed + notarized; Android APKs are
  release-signed.
- Nothing about the Google Play or direct-download builds was affected; this is
  a Microsoft Store listing issue only.
