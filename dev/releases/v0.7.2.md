# Airclone v0.7.2 — mounted drives get out of their own way

A mounted drive stalled while it was uploading: other folders would not list and
thumbnails would not draw until the upload finished. Airclone was handing rclone
exactly one mount setting and taking stock defaults for the rest, and several of
those are wrong for a file manager.

## What is new

- **Mounted drives are tuned for browsing, not just for copying.** Reads are now
  cached on disk, so the second visit to a folder is local instead of another
  download. Files open with a small first read rather than a 128 MiB one, and
  Windows is told it can trust a file's details for five seconds instead of one.
- **Every one of those settings is yours to change**, in two places that agree
  with each other. **Settings → Mounts** holds the defaults new mounts start
  from. The mount dialog has a **Tuning** line that shows what this mount is
  about to use — `Cache: full · 10Gi · 24h` — and opens if you want to change it
  for this mount only. Change something and the line says so, with one click
  back to your defaults.
- **Mount as a network drive** is now offered on Windows. Off by default. Turning
  it on stops Windows treating the drive as local storage, so its search indexer
  leaves it alone.

## Notes for the curious

The obvious suspect was parallel transfers, and it was the wrong one — raising
that would have made things worse, because the part of rclone that uploads from
a mounted drive already runs several at once. The stall was on the *reading*
side. Airclone had been mounting in a mode where, in rclone's own words, "files
opened for read only are still read directly from the remote": every thumbnail
was a fresh download, every time you opened the folder, and each one began by
asking for a 128 MiB chunk. Put an upload alongside that and everything queues.

The change worth knowing about is the disk cache. Mounted drives now keep what
they read, capped at 10 GiB and 24 hours — **per mount**, so three mounted drives
can use three times that. Both numbers are in Settings → Mounts.

## Honest about what was measured

The settings are verified to take effect: each one was read back off a running
engine and confirmed to have arrived. That check was not ceremony — rclone
silently ignores a setting it does not recognise, so "no error" would have
proved nothing, and a typo would have shipped looking exactly like success.

What has *not* been measured is the improvement itself. There is no before/after
timing in this release, and no percentage is claimed. If your mounted drive was
stalling while it uploaded, this release is the thing to try; if it still does,
that is worth reporting, because it would mean the cause is somewhere else.

## Also in this release

- The "Advanced" section used when adding a remote is now shared with the mount
  dialog, so both behave the same way.

## Verified

- Mount options confirmed on a live engine, read back rather than assumed:
  cache mode, cache size and age, read chunk size and its growth limit,
  directory cache time, fast fingerprinting, and the attribute timeout.
- Windows, macOS, Linux, Android: full test suite green (724 tests).
