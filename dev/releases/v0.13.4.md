# Airclone v0.13.4 — Web UI security fixes, and --webui on Linux

> **This release has no Linux downloads.** The AppImage, tar.gz and Flatpak
> failed to build. Get the Linux versions from the
> [latest release](https://github.com/GigaionLLC/Airclone/releases/latest), which
> includes everything below.

## If you have turned on the Web UI, update

The Web UI is **off by default**. If you have never switched it on in Settings,
or started Airclone with `--webui`, none of the security fixes below affect you
and nothing on your machine was exposed.

If you have, three things were fixed. All three needed someone to already be
signed in to your Web UI — they are about what a signed-in session could reach
beyond what it should, which matters most if that session was ever someone
else's.

**A signed-in session could learn the engine's own password.** Airclone runs
rclone in the background, protected by a password the Web UI is supposed to
stand in front of. One of the requests the Web UI allowed returned that
password. With it, a session could talk to rclone directly and skip every
restriction the Web UI applies, including the ones that stop it running
commands on your computer. That request was never used by the app itself, and
it is now refused.

**A signed-in session could share your whole drive with no password.** Sharing a
folder over WebDAV, FTP or similar from the Web UI requires a username and
password before it will listen on your network — but that rule was being checked
by the page in your browser, not by your computer. Anything sending requests
directly skipped it, and could publish your drive to your network with no
password at all. Your computer now enforces the rule itself. Sharing with no
password still works when it is only reachable from the same machine.

**"Upload from URL" could be pointed at your own network.** It makes your
computer download a web address. From the Web UI, that address could be your
router, another device on your network, the computer itself, or — on a cloud
server — the hidden address where the server's own credentials are kept, with
the result saved somewhere the session could read. The Web UI now only fetches
addresses on the public internet. The desktop app is unchanged, so uploading
from a local address still works there.

## `--webui` works on Linux without a display

Running the Linux AppImage with `--webui` crashed straight away on a machine
without graphics — a server, a container, or WSL:

```
Couldn't open libGLESv2.so.2: cannot open shared object file
Aborted (core dumped)
```

That is exactly where you would want to run the Web UI. Airclone was creating
its window before checking whether you had asked for one. It now starts with no
window and needs no graphics at all.

On Windows the same fix stops `--webui` from opening an empty window and leaving
it on screen.

## `--version` and `--help`

Both now exist, and both answer without starting anything:

```
$ airclone --version
Airclone 0.13.4
```

`--help` lists the options that change how Airclone starts.

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- This release is on GitHub only for now and has not been sent to any app
  store. Google Play and the Mac App Store are on v0.13.2; v0.13.3 is in Apple
  review.
- The security findings came from a deliberate review of what a Web UI session
  can reach, done while planning user accounts for the Web UI. That planning
  continues; these fixes did not wait for it.
