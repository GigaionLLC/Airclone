# Airclone v0.13.5 — Linux downloads are back

**v0.13.4 was released without its Linux downloads.** A change to how Airclone
starts on Linux did not build, so the AppImage, tar.gz and Flatpak were missing
from that release. The Windows, macOS and Android downloads were fine.

This release puts the Linux downloads back, and includes everything from v0.13.4,
so Linux users should install this one. If you are on Windows, macOS or Android
and already have v0.13.4, there is nothing new here for you except the Flatpak
notes below, which do not apply to you.

## `--version`, `--help` and `--webui` on Linux

What v0.13.4 set out to do now actually works.

`--version` and `--help` answer straight away, with no window and no graphics
needed:

```
$ ./Airclone-x86_64.AppImage --version
Airclone 0.13.5
```

`--webui` is different on Linux. Airclone's engine needs OpenGL ES libraries to
start, even when no window is shown. If they are missing it used to crash with
`Aborted (core dumped)`. It now says what to install instead:

```
sudo apt install libgles2      (Debian, Ubuntu, WSL)
sudo dnf install mesa-libGLES  (Fedora)
```

If you tried `--webui` on WSL or a server and saw it crash, install that package
and run it again. On a machine with no OpenGL libraries at all, `--webui` still
cannot start on Linux.

## The Flatpak now checks for updates

The `.flatpak` on this page told you "Airclone updates through Flathub", and
never checked for new versions. Both were wrong. Airclone is not on Flathub, and
a Flatpak installed from a file does not update itself: `flatpak update`
refreshes the system parts it runs on, never Airclone.

It now checks for new releases like the other downloads, and tells you when one
is out. To update, install the new `.flatpak` over the old one.

## The Flatpak explains why it cannot mount

Mounting a remote as a drive does not work in a Flatpak, and nothing Airclone
does can change that: Flatpak runs apps in a sandbox, so a mounted drive would
only be visible to Airclone. Before, the only place that said so needed Advanced
mode to find, so most people just found the feature missing.

It is now explained wherever you would look:

- **Settings → Mounts**, in any mode
- the **Mount as a drive** button, which now links to the AppImage
- typing `rclone mount` in the console

If you want to mount drives on Linux, use the AppImage or the tar.gz.

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- This release is on GitHub only and has not been sent to any app store.
- The Web UI security fixes are from v0.13.4 and are included here. If you use
  the Web UI and skipped v0.13.4, see [its release notes](https://github.com/GigaionLLC/Airclone/releases/tag/v0.13.4).
