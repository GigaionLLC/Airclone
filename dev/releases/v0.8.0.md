# Airclone v0.8.0 — backups, and a scheduler that tells you the truth

Scheduling has been in Airclone for several releases. A user looked for it and
could not find it, which was fair: every door to it sat behind advanced mode,
behind a 700 dp window, and behind a two-pane layout you had to arrange first.
This release makes it findable, makes it safe to leave running unattended, and
builds backups on top of it.

## Back up a folder

**Settings → Automation → Back up a folder.** Three answers — what, where, how
often — and it shows you the destination before creating anything.

A backup is a saved task with its dangerous options taken away, and the three
constraints are what make the word honest:

- **Copy only, never sync or move.** A backup that syncs deletes your history
  the moment the source loses a file — which is exactly when you need it.
- **Overwritten files are kept**, renamed aside, so there is a version history to
  restore *from*.
- **Never a dry run**, the worst failure available: it looks like it worked every
  night.

Those are applied when the backup is created and enforced again every time it
runs, so a task edited through the raw advanced dialog cannot run as something
other than what its name says.

Backups land in `<destination>/Airclone/Backups/<device>/<folder>`. The device
segment is there because two machines backing up to one remote would otherwise
merge, and the first sign of that is a restore putting a laptop's files on a
phone.

## Restore

A backup destination is an ordinary remote folder, so **restore is the file
browser you already know**. The restore button on a backup opens its destination
in the other pane, and copying back out of it goes through the same conflict
preflight as every other transfer — restoring *over* a live file asks before it
overwrites.

That is deliberate rather than lazy. A bespoke restore path would have had to
grow its own version of that guard, later and worse.

## Old versions, and deleting them carefully

Replaced files are kept for **30 days by default** (0 to 365, your choice, in
Settings → Automation). Cleaning them up is a button on each backup, never a
timer, and the dialog you confirm is itself the dry run — the list you are
looking at was produced by exactly the code that will act on it.

A prune is a delete loop over a remote, which is the most destructive thing this
app does, so every uncertainty resolves to *do not delete*:

- The current file is never touched.
- A version whose current file no longer exists is **kept** — it is the only copy
  left, and precisely what you came looking for.
- A version with no modification time is kept; unknown age is not "old enough".
- More than 500 to delete and it **refuses entirely** rather than deleting some,
  because a pass that large is more likely a bug than a real backlog.
- If it cannot read the folder, it deletes nothing.

## Camera-roll backup on Android

**Settings → Automation → Back up your photos.** Your camera roll by default,
with a picker to add more folders, mirroring the folder structure to
`Airclone/Photos/<device>/`. Videos are included with their own toggle, since
they dominate the byte count and the first run's duration. Wi-Fi only by default,
because a 40 GB roll on cellular is a bill. Copy only, like every backup.

It runs in the background through Android's WorkManager, with no new permission.

**Worth knowing:** Android 12 and later refuse to promote a background-started
periodic wake to the foreground, so each wake works within a plain background
budget. A large first backup therefore proceeds in slices across several wakes
rather than finishing in one.

## Scheduling you can find, and trust

- **Settings → Automation** is a new, ungated home: what a schedule means on your
  platform, every scheduled task with its next run and last outcome, and a way in.
- **Saving a task no longer needs two panes arranged in advance.** A From/To
  picker asks for both ends directly.
- **A repeating Sync now always has a delete cap** — 100 files by default, shown
  in the editor rather than applied invisibly. Sync deletes whatever the source no
  longer has; if the source is ever missing, that is the whole destination.
- **Tripping the cap pauses the whole scheduler** until you have looked, with a
  banner naming the task and quoting the engine. Global rather than per-task,
  because the causes — an unmounted drive, an expired token, a renamed folder —
  are rarely confined to the one task that noticed.
- **A scheduled Sync refuses to run against a source that is empty or
  unreadable**, and records why. The cap limits the blast radius; this is the
  guard for a destination small enough that the cap would never trip.
- **Airclone tells you which of the runners owns each schedule**, and where to
  look. There are three — the in-app tick, an exact OS trigger, and a shared
  background poll — and "it did not run" is not a diagnosis until you know which
  one was supposed to.

Background scheduling on Windows now uses **exact triggers for daily and weekly
schedules and one shared job for interval ones**, because a 09:00 task should
fire at 09:00 and an "every two hours" task is already polling by nature. The
poll wakes every 15 minutes by default and is configurable from 5 to 60.

**Uninstalling Airclone on Windows now removes its scheduled tasks.** They used
to be left behind, firing forever against an executable that no longer existed.

## An optional tree view

A fourth view mode on desktop: one pane as an expandable hierarchy, lazily loaded
one folder at a time, with Name, Size and Modified. A selection can span folders,
and transfers ask once per source folder.

There is no expand-all and no auto-expand, on purpose — every expansion is a
round trip, and a tree that opens forty folders turns a browse into a bill.

## Android TV fixes

Three, from a user watching films on a set:

- **The blue rectangle that sat on every movie is gone.** It was our own focus
  ring, drawn around the video surface while that surface was briefly 36 pixels
  wide under the loading spinner — and never re-measured when it grew.
- **The D-pad no longer drifts onto the ⋯ menu** while you move through a list.
  Right on a focused row opens that row's actions instead.
- **The music player has previous and next.** A remote has no swipe and no click
  target, so a player with only play/pause is one you cannot get out of.

## Known limits

- **macOS and Linux run schedules only while Airclone is open.** launchd and
  systemd-user are designed and not built; a missed run is caught up once on next
  launch.
- **iOS has no scheduling and no photo backup**, and is not planned to.
- **Nothing prunes old versions on a timer.** Retention is a window you set and a
  cleanup you run.
- **A phone cannot create a raw transfer task** — the transfer-options dialog does
  not fit a narrow screen. Backups and photo backups can be created there.
- The tree view has no expand-all under a node, and type-to-jump searches only
  the visible rows at the root.
