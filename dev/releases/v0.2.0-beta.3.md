# Airclone v0.2.0-beta.3 — command console, native config encryption & offline QR

**Airclone is a modern, cross-platform GUI for [rclone](https://rclone.org/)** — one point-and-click
file manager for 70+ cloud storage systems (S3, Google Drive, Dropbox, OneDrive, SFTP, WebDAV, …) on
Windows, macOS, Linux, and Android. This beta adds a first-class **in-app rclone command console**,
lets you **encrypt your rclone config** (and change/remove that encryption) without leaving the app,
and introduces an **offline encrypted QR** for moving your remotes to your phone with no network at all.

## Highlights

**Command console — run any rclone command, in-app (desktop)**
- A new **console** pane: type any rclone command (`copy`, `lsjson`, `size`, `tree`, …) with **live
  autocomplete** for subcommands, flags, and your remotes, and **doc links** straight to rclone.org for
  each command and flag.
- Commands run as jobs in the transfer queue with **live streaming output** and a **Stop** button
  (Stop actually cancels the running rclone command). It lives inside the existing tab/split system,
  so a console can sit beside a browser or another console.
- **Safety-railed by construction**: it dispatches structured argv (never a shell — injection is a
  non-issue), gates commands by an allowlist (secret-leaking / server / config-mutating verbs are
  blocked), refuses credential-dumping verbosity (`-vv` / `--dump`), and **redacts secrets** from the
  output and history before they’re ever shown. Advanced-Mode-gated; off by default.
- Hardened by a 14-agent adversarial review (22 findings fixed), including blocking any command that
  smuggles a server/config/dump global flag (e.g. a safe verb + `--rc`).

**Native rclone config encryption — encrypt / change / remove**
- New **Settings → Config** controls: **encrypt** a plaintext `rclone.conf`, **change** its password,
  or **remove** encryption — using rclone’s own `config encryption` under the hood.
- The password is held for the session and can be saved to your OS keychain (with optional biometric
  unlock), exactly like unlocking an already-encrypted config. Your config is **backed up first**, and
  the engine is quiesced around the change so a background token refresh can’t race the rewrite.
- Hardened by an adversarial review (8 findings fixed) — no plaintext copy left behind when you
  encrypt, in-flight transfers are protected, and a wrong/interrupted change can never strand the wrong
  password. Desktop + Android (it needs the rclone binary; the in-process engine can *use* an encrypted
  config but not change its state).

**Offline encrypted QR — move your config with no Wi-Fi**
- The existing “Send to phone” streams your config over an encrypted LAN channel — but that needs both
  devices on the same network. **Offline QR** puts your **whole (compressed, AES-256-GCM-encrypted)
  config inside a single QR code**, unlocked by a code you choose. Scan it on your phone and enter the
  code — everything transfers offline; the code is never in the QR.
- Encryption uses the memory-hard **Argon2id** KDF (a static QR is a photographable artifact, so a fast
  KDF wouldn’t do), and the scanner caps the unlock cost an untrusted QR can demand. Adversarially
  reviewed for the untrusted-scan surface.

**Smaller things**
- **Ctrl+F** now works on the Home start page too (filter favorites / recents / remotes by name) — it
  previously only focused the filter once you were inside a remote.
- Fixed live transfer progress: per-job byte/speed/ETA stats now light up correctly (the stats group
  was keyed by the wrong job id).

## Notes
- This is a **beta** — the console, config-encryption, and offline-QR flows are new; the offline-QR
  phone-scanning path in particular is best exercised on a real device. Please report anything odd.
- Everything continues to work in either engine (spawned binary or in-process) on desktop.
