# Airclone v0.8.3 — an empty card reader could blank the whole window

If Airclone opened as a grey, empty window on Windows, this release fixes it.
That is the whole point of this release, and it went out quickly for that reason.

## The blank window

A user on Windows 10 reported Airclone starting up with nothing in it — no
sidebar, no files, just flat grey. It was not hanging and it was not failing to
launch. It had drawn, and what it had drawn was empty.

The cause was a card reader with no card in it.

When Airclone starts it asks Windows which drive letters exist, C through Z. A
card reader sitting empty does not answer "no" to that question — it refuses the
question, with `The device is not ready`. Airclone took the refusal as a fault
rather than as an absent drive, and the fault spread: the drive list is read by
the sidebar and by both file panes, so all three went blank at once. One empty
slot on the machine took out the window.

**A drive letter that cannot be read is now simply not listed.** Everything else
appears as usual. This also covers the same shape of problem elsewhere — a
disconnected network drive, an optical drive with no disc, a card reader you
never use.

If you were affected, you do not need to change anything: unplug nothing, and the
reader can stay empty.

## And a fix for the next one

The bug above was hard to report, through no fault of the person reporting it.

When part of Flutter's interface fails to draw, a release build replaces it with a
flat grey rectangle **containing no text at all** — the explanation is compiled
out. So there was nothing on screen to describe, and the only report anyone could
give was "nothing shows up". The cause had to be worked out from a screenshot of
an empty window.

A part of Airclone that fails to draw now says so, shows what went wrong, and
points at **Settings → Diagnostics → Problem report**, which already had the
details the whole time. The rest of the app keeps working, as it did before.

Nothing about this is sent anywhere. The problem report is local and you choose
whether to share it, exactly as before.

## Also in this release

- **Importing a config now lets you replace colliding remotes one at a time.**
  Each remote already on this device gets its own **Replace** checkbox, and
  checking it drops the "import under a different name" box for that remote,
  because you are no longer making a second copy. A **Replace all** checkbox at
  the top sets every one of them at once.
- **The Flatpak now explains the mounting limitation before you hit it**, in the
  docs and the store description rather than only in an error message.

## Getting it

Windows, macOS, Linux (AppImage, Flatpak, tarball) and Android builds are on the
release page. The Linux packages introduced in v0.8.2 are unchanged apart from
the fixes above.
