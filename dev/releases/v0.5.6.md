# Airclone v0.5.6 — you can finish creating a remote again

Completes the response to the Microsoft Store certification report of 2026-07-29.
v0.5.5 fixed the runtime and clean-uninstall findings; this release fixes the
functionality one — which turned out to be unrelated to those, and to be a real
bug in remote creation that affected everyone.

- **Answering a question while adding or editing a remote no longer fails.**
  Most providers ask a follow-up question during setup. Every answer was rejected
  by the rclone engine, because the request omitted a field rclone requires
  (`parameters`) on the continue step, so setup could not be completed for those
  providers. Both "add remote" and "edit remote" are fixed.
- **The command console now tells you where to do the thing instead.** Commands
  that the console refuses on purpose — `config`, `mount`, `serve`, `rc` and
  friends, which change your configuration, print stored secrets, or start
  servers — used to fail with a flat refusal and no way forward. Each now names
  the place in Airclone that does the job: adding a remote points at the **+**
  next to CLOUD in the sidebar, `mount` at "Mount as a drive", and so on.
- **A mistyped command says it is mistyped.** `lss` used to be reported as though
  it leaked secrets; it now simply says the command is not recognised.
- **A refused *flag* now blames the flag, not the command.** `ls remote: --rc-addr …`
  said `"ls" is not permitted`, which was misleading — `ls` is fine, the flag is
  not.

## Notes
- Still **pre-1.0**. Windows `airclone.exe` + installer are code-signed (Gigaion,
  LLC) and bundle a verified rclone engine; macOS is Developer ID signed + notarized;
  Android APKs are release-signed.
- Everything in v0.5.5 is included: the app-local Visual C++ runtime (so a clean
  Windows machine needs nothing else installed), engine shutdown on window close,
  and clean uninstall.
