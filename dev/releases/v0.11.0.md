# Airclone v0.11.0 — files move through the Web UI, and it is HTTPS now

The Web UI could show you your files. Now it can hand them to you, take them back, and it does all
of that over an encrypted connection.

## Download and upload

**Download** sends a file to the browser you are using. Previously "Download" meant "copy this to a
folder on the server", which over a remote session is almost never what you meant — you are sitting
at the browser, not at the server. In the Web UI it now does the obvious thing. Select files, choose
`Download`, and they arrive as ordinary browser downloads.

**Upload file…** in the pane menu picks a file from the machine you are browsing with and writes it
into the folder you are looking at.

One refusal worth knowing about: **an online-only file will not download.** If only a placeholder is
on the server's disk — OneDrive Files On-Demand, iCloud, Proton Drive — downloading it would quietly
pull the entire file down first, on the server's connection and possibly on someone's metered plan.
Airclone stops and tells you, rather than doing it silently.

## HTTPS, and no plain HTTP at all

The Web UI now serves over TLS only. There is nothing to enable and no plain-HTTP option, because
browsers have stopped treating plain HTTP as a neutral choice — they upgrade it or interrupt it, so
an HTTP service is already a degraded one.

**Your browser will warn you the first time, and that is expected.** Airclone signs a certificate
for your own machine, and no certificate authority can vouch for a computer on your home network the
way one can for a public website. So rather than hide that warning, Airclone shows you the
certificate's **fingerprint** in Settings → `Remote access`. Compare it with what your browser
shows, once, and continue.

That is a deliberate choice. Making the warning disappear would have meant teaching you to click
through security warnings, and the next one might matter.

The certificate is generated once and kept, not made fresh at every start — otherwise each restart
would invalidate the exception your browser stored and look like a new problem.

**Bringing your own certificate.** Put `cert.pem` and `key.pem` in the `webui/imported/` folder
beside Airclone's settings and it uses those instead, which is the hook for anyone renewing
certificates from a script. Airclone leaves its own pair alone, so removing yours falls back rather
than breaking.

## Also

The sign-in cookie is now always marked `Secure`. It used to depend on detecting TLS in front of
Airclone, which could not be relied on; there is no unencrypted connection left for it to be wrong
about.

## Not yet

- **Uploads do not resume.** A dropped connection means starting that file again.
- **Downloads are one file at a time** — no "download this folder as a zip".

## Notes

- Windows builds are signed; macOS builds are Developer ID signed and notarized.
- The Web UI is desktop and headless only. Android and iOS builds do not contain it.
