# Airclone v0.13.2 — your Desktop was there all along

Two bugs found by a user running v0.13.1 on Windows, both reported within minutes
of each other, and both worse than they first looked.

## OneDrive, iCloud, and your own Desktop were invisible

The report was "I don't see the OneDrive folder, but it shows up in Explorer just
fine." It was not Airclone hiding it. rclone's local backend treats a Windows
reparse point as a symlink and **skips it**, so the folder never arrives in the
listing at all: no error, no warning, nothing to click. A folder that Explorer is
showing right next to us simply appeared not to exist.

Measured on the reporter's machine, listing their home directory:

| | |
| :--- | :--- |
| Before | 83 folders, no `OneDrive` |
| After | 97 folders, `OneDrive` present |

Four of the newly visible ones matter, and this is the part that makes it a real
bug rather than a curiosity: `OneDrive`, `iCloudDrive`, and — because OneDrive's
Known Folder Move redirects them into it — **`Desktop` and `Music`**. A file
manager that cannot show you your own Desktop is the severe version of this, and
it is the default state of a stock Windows install with OneDrive turned on.

The same rclone default hides a symlinked folder on macOS and Linux, so this is
fixed for all three.

**Nothing else changed.** The fix applies to listing a folder and to nothing
else, deliberately: once a folder is visible, every other operation already
worked. Turning it on globally would also change what a *sync* does — copying
symlinks as their contents, on every platform — and making a folder visible
should not quietly rewrite what a transfer means.

## A playback error was showing the engine's password

The second report was a `.m3u8` that played in a browser and not in Airclone. The
error card read:

```
Failed to open http://airclone:<the engine's live password>@127.0.0.1:56587/...
```

Airclone puts the engine's credential in the URL on purpose, because the
alternative — an HTTP header — is global in the media player and would be
replayed to any host a playlist names. Scoping the secret to the one request was
right. Printing the result on screen was not.

**If you have seen this error, you do not need to do anything.** That password is
generated fresh every time the engine starts and only ever works against
`127.0.0.1` on your own machine, so restarting Airclone retires it. It is fixed
because the first thing anyone does with a playback error is screenshot it, which
made this a secret on the one surface designed to be shared.

Error messages now go through the same redaction the diagnostics report uses, so
the whole card is safe to send to us. Your account name is removed from file
paths there too.

## And the playlist itself now explains the problem

A `.m3u8` is not media. It names other files by a path relative to itself, so a
copy saved on its own has nothing to point at, and the player fails naming a file
you have never heard of. The error now says that, and points at the thing that
does work: **Tools → Open network stream**, with the address you downloaded it
from.
