# Airclone v0.7.3 — rclone 1.75.1

Airclone bundles rclone and does all its work through it, so an rclone security
release is an Airclone release. This one is worth taking.

## What is new

- **The bundled engine is now rclone 1.75.1**, up from 1.75.0. It is a security
  release, and several of the fixes land on things Airclone actually does.
- **Nothing else changed.** No new features, no UI changes. If you are on 0.7.2
  and everything is working, this is purely an engine update.

## Why it matters

The fixes below are the ones that touch surfaces Airclone ships. Full detail is
in [rclone's changelog](https://rclone.org/changelog/).

- **Opening archives is safer.** Airclone can browse and extract archives, and
  rclone 1.75.1 fixes a path-traversal flaw where a maliciously crafted zip
  could write files outside the folder you extracted it into, plus several
  related problems with entries that escape the directory being listed. If you
  ever open zips you did not create, this is the reason to update.
- **Local folders stay inside their boundaries.** A planted symlink could expose
  details of files outside the folder being browsed, and a specific kind of
  partial read of a symlink could crash the engine. Previews use exactly that
  kind of partial read.
- **Credentials no longer follow a redirect.** Headers configured for one server
  could previously be sent to a different one, or over an unencrypted
  connection, if a request was redirected.
- **Passwords stay out of the log.** Config values supplied through environment
  variables — which is how Airclone hands rclone the password for an encrypted
  config — are now redacted in rclone's own logging.
- **Underlying library CVEs** in Go's cryptography and image packages are picked
  up by the rebuild.

Two more that are not security, but matter for how Airclone runs:

- **Long sessions use less memory.** Two leaks were fixed in the part of rclone
  that tracks transfer statistics for a long-running engine, which is exactly
  how Airclone runs it — one engine, alive for as long as the app is.
- **A family of "the file arrived truncated" bugs is fixed** across many storage
  providers: an upload whose source ended earlier than expected could be
  recorded as successful while storing a short or corrupted file.

## Verified

Before the pin was moved, a real 1.75.1 binary was checked (its SHA-256 matched
rclone's published checksums) against the three things Airclone depends on most:

- serving a byte range still works — the path previews and thumbnails use;
- adding a remote still speaks the exact protocol Airclone expects, the
  regression that once cost a Microsoft Store certification cycle;
- and the mount settings added in 0.7.2 still take effect, checked by reading
  each one back off a running engine, which matters because 1.75.1 changed a lot
  inside the mount layer.

Full test suite green (724 tests) on Windows, macOS, Linux and Android.
