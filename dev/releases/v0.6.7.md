# Airclone v0.6.7 — "Copy to…" and "Move to…" ask before overwriting

Copying or moving a file into a folder that already holds that name used to
replace it silently. Now it asks — the same **Skip / Replace / Keep both**
prompt you already get when pasting or dragging.

The two menu items also inherit the safety fix from v0.6.5: if Airclone cannot
read the destination folder — an offline backend, an expired token, a folder
without permission — it transfers **nothing** and tells you, rather than
assuming the folder is empty and writing over whatever is really there.

## What this does not cover yet

Being specific, because a half-closed gap is worse than a known one: downloads,
uploads, the quick dual-pane transfer button, the inspector's download and the
mobile multi-select actions still transfer without a collision prompt. Bringing
every route through one safety check is a larger piece of work, planned
separately rather than half-done here.
