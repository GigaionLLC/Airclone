# Airclone v0.9.0 — Airclone in a browser, and Linux finally ships its engine

Two things worth your attention. Airclone can now serve its own interface to a
browser, so a machine with no monitor can still be driven from your phone. And
the Linux builds now carry the rclone engine they always claimed to.

## The Web UI

`airclone --webui`, or **Settings → Remote access**, and Airclone serves itself
over HTTP. Open it from any browser on your network.

**Everything still happens on the machine running Airclone.** This is the part
worth reading twice:

- Mount a drive from your phone and it mounts **on that machine**, not on the phone.
- Browse a disk and you are browsing **that machine's** disks.
- Start a 200 GB sync and **that machine** does it, at its network speed, and it
  keeps going after you close the tab.

Your browser draws the picture and sends your intent. It does not touch a file.

It is not a cut-down web client, either. It is the same app — the same panes, the
same remotes, the same transfers — compiled for the browser. One address serves
both layouts: a narrow screen gets the phone interface, a laptop gets the desktop
one, and resizing the window switches between them.

### It is locked by default, and it stays that way

There is always a password. There is no flag, setting or build that turns
authentication off, because what sits behind that password is every remote you
have configured.

- **It listens only to the machine itself** until you say otherwise. Reaching it
  from another device is something you opt into, and Airclone says so plainly
  when you do — in the log and with a banner that stays up the whole time.
- **A password is generated on first launch** and saved next to your rclone
  config, in `webui.env`. Delete that file to get a new one, or press
  **New password** in Settings, which also signs out everyone currently signed in.
- **Nothing but the sign-in page is served** until you are signed in. A scanner
  that finds the port gets a 4 KB page, not the application.
- **Airclone does not hand the browser the rclone API.** rclone's own
  documentation is blunt that access to that API is equivalent to shell access;
  so the Web UI forwards only the specific operations Airclone itself uses and
  refuses everything else, including anything it does not recognise.

The connection is plain HTTP. On a home network you control that is usually
fine. Across anything you do not control, put it behind a reverse proxy that
terminates TLS. Full details: [the Web UI guide](../../docs/guide/web-ui.md).

## Linux: the engine really is inside now

The Linux packages said the rclone engine was included. It was not — they carried
the in-process library but no `rclone` binary, and that had a consequence beyond
the missing file.

Airclone prefers a bundled binary and falls back to the library. With nothing
bundled, it fell through to **whatever rclone happened to be on your PATH** —
any version, any age — and on a machine with none, it sat on first run
downloading one. Since Airclone's users are mostly people who already have rclone
installed, that was the common case rather than an edge case.

The AppImage, Flatpak and tarball now each carry a checksum-verified rclone
binary, and the build fails if any of them does not. Nothing to download on first
run, and the engine you get is the one that was tested with this release.

## Two windows no longer fight

Opening Airclone a second time used to kill the first one's engine. Both copies
tracked the engine through one shared file holding one process id, and every
launch killed whatever was in it — so the second window tore the engine out from
under the first, mid-use, breaking any mount it was holding.

Instances now recognise each other and leave each other's engines alone. Cleaning
up an engine orphaned by a crash still happens, but only when nothing else is
running.

## The tree view works on a phone

The tree was desktop-only because the row could not fit indentation alongside the
Size and Modified columns. On a narrow screen those two columns are now dropped
and the space goes to indentation — which is the part that makes a tree a tree.
**View → Tree** on a phone.

## Smaller things

- The phone layout used to head the local disks **"This phone"**. In the Web UI
  those are the host's disks, so it now reads **Host computer** — the old wording
  said the opposite of the truth about where your files were.
- The README has a proper **Downloads** table: every platform, store link and
  direct download side by side, with links that always resolve to the newest
  release.
- A weekly job now opens a pull request when upstream rclone moves ahead, so the
  engine version is proposed and reviewed rather than drifting quietly.

## Notes

- The Web UI is **desktop and headless only**. A phone is not the machine you
  point a browser at, so the Android and iOS builds do not carry it.
- Moving files between the device you are browsing *from* and the host is not
  part of this release. "Local" in the Web UI means the host's disks.
- The Web UI is one account: one username, one password.
