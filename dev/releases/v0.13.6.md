# Airclone v0.13.6 — mounting works on Linux

## Mounting on Linux never worked. It does now.

If you tried **Mount as a drive** on Linux and it failed, it was never going to
work, in any earlier version.

The mount manager only offered drive letters: "Auto (next free letter)" and D:
to Z:. Linux doesn't use drive letters, so every choice was refused, with an
error like `cannot open: *: no such file or directory`. Nothing about your setup
caused it.

On Linux and macOS the mount manager now asks for a **folder** instead. It
suggests one in your home folder, such as `/home/you/Airclone/gdrive`, and you
can type another or press **Choose…**.

- Airclone creates the folder if it doesn't exist.
- The folder must be empty, so nothing already in it is hidden while the drive is
  mounted. A folder with files in it is refused before anything happens.
- Folders under system locations like `/tmp` or `/etc` are refused.
- If FUSE isn't installed, the mount manager says so and names the package
  (`sudo apt install fuse3`), instead of showing rclone's raw error.

Windows is unchanged and still mounts to a drive letter.

**macOS:** the mount manager now asks for a folder there too, which is what macOS
needs. But mounting on macOS hasn't been tested end to end, so we're not claiming
it works yet.

**The Web UI** still offers drive letters only. It runs in your browser, which
can't tell what system is serving it, or create a folder there. Mounting through
the Web UI works when Airclone is running on Windows. On Linux or macOS, mount
from the Airclone app on that machine.

## Mounting from the Flatpak, with a permission you grant

v0.13.5 said a Flatpak can't mount and that no setting changes that. **That was
wrong,** and we're sorry for saying it.

A drive mounted inside the Flatpak sandbox would only be visible to Airclone. So
Airclone now mounts through a small helper that runs outside the sandbox, where
every program can see the drive.

That helper needs one permission, and Airclone doesn't ask for it by itself. It
lets Airclone run commands on your computer outside the sandbox, not only the
mount, so whether that's worth it is up to you. To grant it, run this once and
restart Airclone:

```
flatpak override --user --talk-name=org.freedesktop.Flatpak com.gigaionllc.airclone
```

- **Before you grant it**, the mount button, Settings → Mounts and the console
  all explain this. The mount button shows that command, with a button to copy
  it.
- **Once granted**, the mount manager reminds you it's using that permission.
- **To take it back:**
  `flatpak override --user --no-talk-name=org.freedesktop.Flatpak com.gigaionllc.airclone`

If you'd rather not grant it, the AppImage and tar.gz mount without it.

## A spare graphics library for WSL and slim systems

On WSL and some slim systems, the AppImage stopped straight away because one
graphics library, `libGLESv2`, was missing, even though the rest of the graphics
setup was there.

The AppImage now carries a spare copy. It's only used when your system has a
graphics driver but not that one library, so it can't get in the way of a working
setup, including NVIDIA's.

On a system like the WSL one that reported this, that should let the AppImage start
with no extra packages. It hasn't been confirmed on that machine yet.

If your system has no graphics driver at all, Airclone still stops and tells you
what to install.
