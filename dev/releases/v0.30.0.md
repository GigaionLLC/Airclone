# Airclone v0.30.0 — keep Airclone running in the tray

## A tray icon on Windows, macOS and Linux (#54)

Airclone now has an icon in the system tray: the notification area on
Windows, the menu bar on macOS, and the status icons area on Linux. Its menu
shows what Airclone is doing and lets you control it with the window closed:

- **Status line**: `Idle`, or what's transferring, how fast, how long is left
  and how much is queued. On Windows it's also the hover text.
- **Open Airclone** shows the window again.
- **Pause all / Resume all** pauses the queue. Queued transfers wait; ones
  already running finish, so no file is left half-written.
- **Bandwidth limit** sets the speed limit for every transfer.
- **Quit Airclone** quits for real. If a drive is mounted, you're asked first.

## Closing the window can keep Airclone running

Settings → Tray → **Closing the window keeps Airclone running in the tray**.
It's off by default, so closing the window still quits, as before. Turn it on
and closing the window only hides it: transfers, mounted drives, servers and
scheduled tasks keep going. On macOS and Linux, where schedules run only while
Airclone is open, this is how you keep them running all day without a window.

If you've never chosen and something is still running when you close the
window, Airclone asks once and remembers your answer.

## Start in the tray when you sign in

Settings → Tray → **Start Airclone in the tray when I sign in** starts Airclone
hidden, with no window, each time you sign in. It's available in the Windows
installer and portable builds, on macOS 13 and later (direct download and Mac
App Store), and in the Linux AppImage and tarball. It isn't offered in the
Microsoft Store build or the Flatpak yet; Settings says why. `airclone --tray`
does the same from the command line.

Only one Airclone window runs at a time now: launching it again while it sits
in the tray brings back the running copy's window. Background runs such as
`--run-task` and `--webui` aren't affected.

## Notes

- **Linux:** the icon needs a tray host. KDE, Cinnamon, Xfce, MATE, Budgie and
  Ubuntu have one; plain GNOME needs the *AppIndicator and KStatusNotifierItem
  Support* extension. Without a host there's no icon, the switch is greyed out
  and closing the window quits. The AppImage and Flatpak include the library
  they need; the tarball needs `libayatana-appindicator3` installed (see the
  README).
- There is no Snap package.
- Android, iPhone, iPad and the Web UI are unchanged.

Full details: [Keeping Airclone in the tray](../../docs/guide/tray.md).
